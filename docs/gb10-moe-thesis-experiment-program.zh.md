**已有工作的边界。**

SeqMoE 已有预测驱动缓存、截止期调度和缓存槽映射；ZipMoE 已有统一内存、多表示缓存及任务图调度。它们是核心基线，不能被描述成只追求简单命中率。[SeqMoE](https://arxiv.org/html/2609.12978v1)、[ZipMoE](https://arxiv.org/html/2601.21198v2)

SlimCaching 已研究 Top-K 共激活导致的缓存决策耦合；DuoServe-MoE 已区分 prefill/decode；Layered Prefill 已讨论 MoE 分块预填充的重复权重加载。因此“共激活”“分阶段”“减少重复加载”都是已有概念。[SlimCaching](https://arxiv.org/html/2507.06567v3)、[DuoServe-MoE](https://arxiv.org/html/2509.07379v1)、[Layered Prefill](https://proceedings.mlsys.org/paper_files/paper/2026/hash/c0f460c6d63599ea870ba9db63dc96a9-Abstract-Conference.html)

ProMoE 已有分块与优先级；HybriMoE 已有动态异构调度；FlashMoE 已学习组合近期性与频次。我们必须比较它们的相关机制，不能依靠弱 FIFO/LRU 或固定 CPU 比例制造优势。[ProMoE](https://arxiv.org/html/2410.22134v1)、[HybriMoE](https://arxiv.org/html/2504.05897v1)、[FlashMoE](https://arxiv.org/abs/2601.17063)

本方案的文献缺口均限定为：这些机制迁移到本机或相互组合后的增量问题。未报告不等于不存在，更不等于方法错误。

**A1：软件上的两级缓存，是否在统一物理内存中存了重复权重。**

来源与假设：独立显存系统中 host cache 与 device cache 对应不同物理资源；GB10 共用物理内存，软件仍可能为同一权重保留源、目标与临时缓冲。不能因统一内存就假定现有指针可直接被当前 CUDA 内核使用，也不能假定复制一定多余。[硬件说明](https://docs.nvidia.com/dgx/dgx-spark/hardware.html)

实验：固定真实专家序列，首先做分配/生命周期账本，标注唯一有效权重、真实副本、临时区和计算工作区。比较①当前复制路径；②保留 GPU 可执行槽、命中不重复复制的小原型；③设备与内核确实支持时的共享映射读取微基准。分别在相同有效专家容量和相同总物理预算下比较，前者测路径成本，后者测容量代价。

指标与图：总预算—唯一可执行专家容量；命中时复制字节/token；kernel 时间与 TPOT。共享读取若导致 kernel 变慢，也必须计入。全驻留模型是参考，受控限额是明确的实验条件。

对应方案：仅当副本/复制有实质代价，才重构槽位与生命周期。单纯减少一遍复制属于工程基础；只有与 A2/A3 的容量收益决策结合并超过已有持久槽方法，才可能支撑更强研究贡献。A1 本身不独立计为算法创新。

**A2：同样一 MiB 缓存，放在不同层是否产生不同的延迟收益。**

来源与假设：频次、未来使用和浅层优先等策略已存在；尚需验证的是，在实际 SSD 与消费者等待下，多给某层空间的收益是否能由频次/缺失数准确替代。

实验：关闭预测，固定自然 token 和执行路径。总缓存不变，把固定额度（起点 64 MiB，按对象大小取整）从层组 a 转到层组 b，其余不变；先分浅/中/深三组筛选，差异明显再细到层。对每次调拨，记录净读取减少与暴露等待减少。比较均匀分配、按访问量分配、预测使用分数，以及基于测得边际收益的离线配置参照。

指标与图：层组×容量的边际延迟收益热图；以读取减少量预测延迟改善的误差；总容量相同下不同分配的 TPOT。缓存副本和工作区占用固定，不能把增加总预算混入调拨。

对应方案：若频次已能解释收益，采用已有频次策略；若延迟收益存在可重复差异且随阶段变化，设计按延迟边际价值分配空间的在线方法。离线配置是诊断参照，不能用确认集调拨结果作为在线已知信息。需要额外比较全局强缓存，避免只战胜人为固定层配额。

**A3：专家之间的依赖是否使独立缓存得分选错对象。**

来源与假设：SlimCaching 已证明其分布式场景存在共激活耦合；本机 fused 消费者、并发 NVMe 和不同权重就绪状态是否有足够强的非加性，需要实测，不能从别的平台推导必然成立。

实验：在少量固定层事件上冻结起始缓存和资源状态，关闭淘汰/预取，分别预置对象 a、对象 b、a+b，测同一消费者的等待。用局部枚举取得固定小预算下的最优预置集合，对比独立分数选择。另做保持每事件 Top-K 和各专家边际频次的重连 trace，用固定缓存评估共激活变化；不在这个对照中引入时间型淘汰，从而避免把时间局部性变化混为共激活效应。

指标与图：单对象收益之和与联合收益的差；小规模最优集合与独立打分的差距；自然 trace 上出现可观非加性事件的比例。若差距仅在构造 trace 出现，不能据此提出面向自然工作负载的贡献。

对应方案：若独立得分足够，保留简单规则；若依赖导致稳定损失，增加小候选组的联合保留评估。不能把“组缓存”声称首创；需证明它利用了当前后端的消费者/服务依赖，且收益大于额外决策开销。

**A4：prefill 结束时的缓存，是否适合 decode 的前几个 token。**

来源与假设：分阶段方法已有；问题收窄为阶段边界的驻留内容和替换成本。大范围 prefill 访问可能留下与短期 decode 不匹配的对象，也可能天然提供良好 warm start，两个方向都允许。

实验：固定 prompt，预填充结束后比较①原样继承；②清空专家缓存；③只根据 prefill 末段真实访问保留相同容量；④利用未来前若干 decode token 构造的不可部署参照。控制同样的 KV、预算和 decode 序列。候选在线方法只能使用 prefill 已知信息，不能读取未来路由。

指标与图：第 1—32 个 decode token 的读取与延迟轨迹；进入稳态所需时间；TTFT、前 16 token 完成时间及完整请求时间。边界预热/替换工作全部计入，不准挪到未计时区域。prompt 先用 256/2048 tokens，生成长度分短回复与较长回复两档。

对应方案：若差异很小，继承即可；若阶段切换损失集中且可用已知信息减少，设计有成本上限的边界保留/预热。与“prefill/decode 各用一个规则”的强基线比较；该子机制可并入 A，不必再单列整章创新。

**B1：预测再准，在 SSD 上究竟需要多长的提前量。**

来源与假设：已有论文已研究准确率与提前量；本实验的用途是定位 GB10 上可行动区域，并判别真正缺的是预测质量、时间窗口还是存储带宽。

实验：固定缓存和 I/O 配置，对相同真实 trace 运行三种信息条件：已有轻量预测器、同一时刻提供完美候选的未来信息参照、零读取成本的放松参照。前两者仍执行真实读盘；第三者只作模拟或全驻留界限，不能当作可部署速度。扫提前窗口 1/2/4/8/16/48 层，只在信息合法可获得的区间评价在线方法。

指标与图：提前量—按期完成率与暴露等待；各层最短准备窗口分布；读取服务量与可重叠窗口。固定缓存的诊断先排除容量干扰，随后 B3 加回有限空间。

对应方案：完美预测仍迟到，优先改读取/表示/窗口；完美预测明显好且现实预测差，才考虑预测器；已有预测接近参照，则不投入训练新预测器。B1 是选择研究方向的支持性实验，不单独算新算法。

**B2：软件需求优先级能否穿透 NVMe 在途预测队列。**

沿用 E1：固定缓冲与读取集合，对照纯需求、整专家需求优先、固定分块需求优先、限制未完成投机量；扫块大小 1/3/9 MiB 与提交深度 1/4/8。相同打包布局、正确对齐，最终 drain 相同任务。

指标与图：需求到来时未完成预测字节—需求响应 p95；吞吐—需求延迟折中。区分软件排队、系统调用/提交、完成三个时间段。再用小量真实前向确认影响。

对应方案：只有最强固定分块/深度不能覆盖实际变化时，才设计块大小与在途额度的联合控制。普通优先队列、分块和暂停预测均为已有基线。

**B3：长窗口的收益是否被受保护缓存占用抵消。**

沿用 E2：相同预测候选、生成时刻、缓存规则与 I/O 配置，对照尽早预约、固定距离再预约、无预测。扫距离 2/8/24/48 层和剩余预算 4/8 GiB。记录预约中、就绪未用、已用保留三段占用。

指标与图：提前量—净额外补读—迟到等待—TPOT；被预测对象挤出的缓存条目的真实后续使用。配对回放记双方独有缺失，而非只统计对某策略不利的事件。

对应方案：若固定距离足够，则调参；若最优开始时刻取决于空间机会成本，则把候选登记、槽位预约和实际读取分开控制。与 SeqMoE 风格保护/淘汰及固定延后强基线比较。

**B4：预测准确率提高，新增正确预测是否真的位于缓存缺失集合。**

来源与假设：已有系统考虑缓存与预测交互；本实验检验的是更昂贵/更远期预测是否提供可兑现的增量信息，避免为已经驻留的热门专家消耗预测和预取资源。

实验：复用至少两种已有预测来源，例如上一 token/相关性表与已有可适配的学习预测器，不先训练新模型。固定缓存初态与观察时刻，比较全部路由 recall、缺失集合 recall、按期补齐缺失数和预测 CPU/GPU 时间。再固定同一候选输出，仅改变准入：概率 Top-N、先过滤驻留/在途再排序、按收益与成本选择的离线参照。预测探测不刷新真实热度。

指标与图：总 recall 与缺失 recall 的关系；新增正确候选的驻留/缺失/迟到分解；预测开销与节省等待。使用不同容量检验排名是否稳定，但不在确认集事后选阈值。

对应方案：过滤已驻留后差距消失，只用简单过滤；缺失对象的概率与服务成本导致排序变化，设计面向可兑现收益的预测准入或按需启用预测器。不能把过滤重复请求本身当创新，也不能仅用一次相同命中率的构造例子证明价值。

**C1：CPU 辅助哪些工作，能得到最大的端到端收益。**

来源与假设：Fiddler/HybriMoE 的异构思路已有，但本机 CPU 用于专家计算、I/O、预测或解码的机会成本不同。不能只比较孤立 GEMV 速度决定分工。

实验：先使用真实 2048×768 三投影和固定权重，測 CPU/GPU 在 token 行数 1/4/16/64、专家数 1/2/4/8 下的成本；再保持总 CPU 核配额不变，对照 CPU 只服务读取/管理、加入专家计算、可用时加入解码。测时包括输入准备、两分支结束和输出归并。CPU 专家支持路径不足时先做微基准，不把上限估算当作系统收益。

指标与图：任务角色×负载的总层延迟；被 CPU 专家计算拖慢的需求服务；CPU/GPU 分工的收益区间。

对应方案：存在明确收益区间才增加专家分担；否则 CPU 保留辅助职责。无收益的 CPU 计算不应进入最终方案以凑功能。

**C2：Arm 不同核组与线程数量是否改变最优资源分工。**

来源与假设：本机此前识别到两类 Arm 核，但不同任务在各核组的收益需要测量；CPU 编号不等于性能等级，先根据实际拓扑映射核组。

实验：同一任务、相同线程数，对照系统默认调度、固定核组、按任务分开核组；再局部扫 1/2/4/8 线程。任务包含读取完成处理、预测表更新、可用的 CPU 专家与解码。固定可用核集合并记录频率/功耗状态，不把更大的核预算误当成亲和性收益。

指标与图：任务×核组的服务时间与 p95；增加线程后的收益/退化；相同总核预算下的端到端时间。只在开发实验发现有意义的任务组合后做前向验证。

对应方案：固定绑核即可解决，属于工程基础；若角色/线程最优配置随推理阶段与瓶颈变化，才考虑运行时配置选择。调参或把任务绑到快核本身不构成强算法贡献。

**C3：独立测得的 CPU/GPU/I/O 成本能否预测并发执行的最优选择。**

来源与假设：HybriMoE 已包含基于性能信息的调度，不能声称首次建模。这里检验共享资源下“独立成本预测的最优配置”是否在实际并发时变为较差配置，以及纠正是否值得。

实验：固定权重、任务量和读取集合，分别测 GPU、I/O＋复制、CPU 专家/解码的单独、两两及共同执行。比较独立成本相加/取 max 的预测，与每个可行并发配置实测完成时间；选择最佳固定配置作为强基线。无需先实现在线控制器。

指标与图：预测最优与实测最优的排序反转频率；误选造成的 regret；并发组合下 GPU 延长与需求延迟。若无法获取 DRAM 计数器，只描述可观测干扰，不断言内存带宽饱和。

对应方案：静态配置已经稳定，结束动态控制分支；排序反转显著且低维状态能预测时，建立条件成本表，按队列/阶段切换少量配置。成本估计、采样和切换开销全部计入。与在线平均成本及最佳固定配置比较，不能只比较未经调优的固定比例。

**C4：压缩权重的读取与物化是否需要不同的提前量。**

沿用 E3：先确认压缩率/解码成本，采用现成 codec 做真实子集原型。比较原始按需、原始预测、压缩按需、压缩预测立即解码、同样读取时刻但延后解码。后两组固定压缩读取字节和候选，隔离转换时刻。

指标与图：完整态占用和转换峰值；解码未用字节；空间挤占补读与解码迟到。压缩源、完整目标和 GPU 计算目标真实同时存在时必须同时计入。

对应方案：有空间/及时性折中才采用分阶段准备，并把 CPU 解码角色加入 C1/C3；否则不引入压缩控制。不同表示缓存及其 DAG 已有先例，增量只能来自预测条件下的转换时机与资源联动。

**从十二项诊断中选择真正能形成贡献的证据。**

| 研究线 | 基础或支持证据 | 至少需要的机制证据 | 算法形成后必须比较 |
|---|---|---|---|
| A | A1 的物理账本 | A2/A3 至少一个显示强基线仍有缺口；A4 用于阶段扩展 | 强全局缓存、频次/未来使用、阶段规则；相同总物理预算 |
| B | B1 的可行窗口 | B2/B3/B4 中的干预能解释并恢复实际等待 | 最佳固定分块/深度/距离、已有截止期和缓存保护机制 |
| C | C1/C2 的角色与拓扑 | C3 证明成本排序变化且可低开销纠正；C4 可选 | 最佳固定分工、独立成本模型、在线平均成本 |

没有满足中间一列，就不能只因实现工作量大而宣称独立算法贡献。三条线都成立，可以形成三个技术章节；只有 A/B 成立，则做两项深入贡献，C 作为系统分析与边界。具体是否满足毕业要求仍须结合学位层次、院系规范和导师要求，不能通过实验数量保证。

**最终评估与动机严格分开。**

方案固定后再做：全驻留与强卸载基线；相同物理预算的总体性能；A/B/C 单独及组合消融；跨请求类别、容量、上下文与生成长度；有条件的第二模型；在线决策开销；输出/权重正确性；退化和失败案例。至少在一个额外工作点验证规则迁移；若只测一个模型一种 dtype，结论明确限定该范围。

不要求一开始跑 2^3 的全组合。先测基础、A、B、C、完整方案，再根据观察到的交互补必要组合。第三模块未成立就不保留对应消融。

共用 12 个开发请求与已有 trace。A2/A3/A4/B1/B4 先离线或局部事件诊断；B2、C1/C2/C3 先真实微基准；B3 用回放筛选再前向。每组只把最有解释力的 2—3 个处理送到端到端验证。之后再冻结来源隔离的确认集、参数与统计口径，避免把十二组扩成不可完成的笛卡尔积。

**可落入论文的结构。**

第一技术章：设备与实际执行路径，A1—A4 揭示缓存的空间成本和延迟价值，形成缓存方法并验证。

第二技术章：B1—B4 揭示预测可行窗口、SSD 服务与驻留冲突，形成读取控制方法并验证。

第三技术章（条件成立时）：C1—C4 揭示任务角色和并发成本，形成资源分配或分阶段准备方法并验证。

系统评估章统一比较总体收益、交互、泛化与代价。这样扩展的是可以独立论证的研究内容，而非仅把同一个预取实验拆成更多编号。
