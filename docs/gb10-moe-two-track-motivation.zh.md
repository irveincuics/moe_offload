# DGX01：分阶段预取与 CPU/GPU 协作的递进动机实验

日期：2026-10-08。版本：v2，按 DGX01 与相关论文的平台差异修订。状态：完成文献、留存环境记录与当前源码核对，尚未执行本文新增性能实验。

本文按当前选题收敛为两条主线：A，存储感知的分阶段预取与驻留调度；B，统一内存下的 CPU/GPU 专家协作。压缩、专家内部计算分块、布局优化和更复杂预测器均作为条件成立后的辅助机制。本文编号优先用于后续实施；旧文档保留文献与历史设计，不将其所有实验继续作为必做项。

总问题：在相同权重、真实路由和有限统一物理内存预算下，如何减少 SSD 权重供给暴露在推理关键路径上的等待，并让已就绪专家更早完成计算？

A 研究权重何时进入内存、何时变得可执行、保留到何时；B 研究权重已就绪或陆续就绪时，CPU/GPU 怎样分工。CPU 无法绕过尚未完成的 SSD 读取。GPU 已经可以有效利用就绪工作时，增加 CPU 可能没有收益。是否存在这种收益是实验问题。

v2 的关键调整：先通过 U0—U2 校准共享内存访问路径、总容量约束及并发服务成本，再固定一个适合本机的数据路径开展 M1—M7。CPU/GPU 的逻辑缓冲类型不再被当作两份独立物理容量；分阶段预取也不强制包含 Host-to-Device 复制阶段。

## 1. 当前基础与文献边界

现有 M0 的真实 BF16 小规模四基线路径检查通过；正式 12 请求实验中 resident/mmap 诊断通过，async 的 11 条完整请求通过补充审计，第 12 条超时，V2 及后续正常路径、重复测时、自然生成阶段未完成。证据见 `/home/cuichengshang/moe_ssd/test/m0/bf16-accept-dev-20260929/acceptance-report.zh.md`。

已有完整 resident 路由可以用于局部性分析、容量回放和选取微基准事件。诊断模式同步执行节点并改变融合，其墙钟时间不可直接作为正常执行的到达时间、重叠窗口或性能基线。

现有 async 是需求读取与复制提交的流水，不等于跨层预测，也不等于按完整专家就绪顺序执行 CPU/GPU。M0 的消费者审计要求 CUDA，未来 CPU 原型需要增加独立的预期执行位置检查，不能直接关闭后端检查。

与最接近工作的关系：

- [SeqMoE](https://arxiv.org/html/2609.12978v1) 已有截止期预取、预测驱动缓存及槽位保护。A 的问题是这些机制用于 SSD 时，准备提前量与真实空间占用、设备在途服务之间是否产生需要新决策的折中。
- [ProMoE](https://arxiv.org/html/2410.22134v1) 已有分块与需求优先级。A 必须比较调优后的固定分块、暂停新增投机提交等机制。
- [HybriMoE](https://arxiv.org/html/2504.05897v1) 已有动态 CPU/GPU 分工和时间线模拟。B 要检验条件成本与权重就绪状态能否纠正具体的分工误选。
- [SSD-LLaMA](https://arxiv.org/html/2609.18110v1) 已有专家打包、SSD 流水及异构分工测量；其 §4.3 一个受控实验中，全 GPU 优于所测 CPU 分担比例。CPU 协作收益不预设为正。
- [ZipMoE](https://arxiv.org/html/2601.21198v2) 已有统一内存上的多表示缓存与重建调度，压缩仅作辅助候选。

文献没有在某配置下报告结果，不构成其方法失败的证据。论文机制适配到本机时记录偏离，不能把简化实现称作完整复现。

跨论文比较对象是机制，不是论文加速倍数。首先在本机固定同一模型、权重精度、路由、预算、布局和算子能力，再比较原理可适配的策略。原论文使用的 FP8/INT4 等不会被悄悄替换为本机 BF16 后称为忠实性能复现。

机制适配记录必须包含：保留的决策逻辑、替换的数据路径、预测来源、执行粒度、图捕获/融合状态、数值格式、内存记账、缺失功能。SeqMoE 风格截止期对照使用同一固定候选时，只能称其调度机制对照，不能声称复现其学习预测器或整体系统。

### 1.3 当前源码的实际路径

`ggml_ssd_source_file::read` 对 direct 请求分配对齐临时区，`pread` 后用 `memcpy` 写入缓存 entry；消费者随后用 `ggml_backend_tensor_set_async` 提交到 CUDA 目标，CUDA 实现调用 `cudaMemcpyAsync`。即使 SSD 缓存命中，这段消费代码仍提交所选范围的复制。

这条路径可抽象为 `SSD -> 对齐读取临时区 -> CPU 可访问缓存 -> CUDA 执行目标`。后面三个对象可能都消耗同一物理内存池中的空间和带宽。不能仅凭函数名判断物理传输位置，也不能仅凭 UMA 宣称这些副本不存在。证据：[读取与缓存实现](/home/cuichengshang/moe_offload/llama.cpp/ggml/src/ggml-backend.cpp:875)、[所选权重复制](/home/cuichengshang/moe_offload/llama.cpp/ggml/src/ggml-backend.cpp:2173)、[CUDA 写入实现](/home/cuichengshang/moe_offload/llama.cpp/ggml/src/ggml-cuda/ggml-cuda.cu:2467)。

`GGML_CUDA_ENABLE_UNIFIED_MEMORY` 只改变该分配函数是否调用 `cudaMallocManaged`，不自动消除上述缓存、复制、调度依赖。GPU 可访问普通系统分配、mapped host 或 managed 指针的支持与行为需分别核查；[CUDA Unified Memory 文档](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/unified-memory.html)区分这些能力和平台模式。当前文档版本不能替代本机 CUDA 12.9 头文件、设备属性与实测。

## 2. 递进顺序与交付

| 阶段 | 问题 | 最小实验形式 | 进入下一步的条件 |
| --- | --- | --- | --- |
| U0 | 本机共享内存究竟支持哪些访问与 I/O 路径？ | 容器、设备、分配能力和缓冲生命周期核实 | 核心能力与未知项有证据记录 |
| U1 | 哪种数据路径适合本机，同预算能存多少唯一权重？ | 当前复制路径、持久可执行槽、可行时共享槽 | 冻结数据路径 P*，完成容量与正确性检查 |
| U2 | 并发是否改变供给或执行速度，原因是什么？ | CPU/GPU/I/O/复制的受控组合 | 得到本机服务曲线，区分可观测干扰与推测 |
| P0 | 比较是否正确且资源可比？ | 补齐 M0、内存账本、低扰动测量 | 新路径正确、资源核算清楚 |
| M1 | SSD 延迟到底暴露在哪里，有多少可优化空间？ | 正常前向画像与对照 | 确认供给等待或执行等待确有占比 |
| M2 / A | 可获得的预测提前量够不够？ | 路由回放、真实读取、预测诊断参照 | 存在按期供给空间，或定位迟到原因 |
| M3 / A | 投机读取是否拖慢真实需求？ | 固定缓冲、同工作量 I/O 回放 | 读取额度/粒度影响需求延迟 |
| M4 / A | 提前占位是否挤出有用权重？ | 容量因果回放再真实前向 | 过早占位和迟到之间存在折中 |
| M5 / B | CPU 能否有效利用 SSD 供给期间的就绪工作？ | 真实专家单层微基准 | 优于同 P* 上调优后的最佳 GPU-only |
| M6 / B | 并发是否使最佳分工发生变化？ | 固定工作量的并发干预 | 条件成本减少可重复的误选 |
| M7 / A+B | 两条主线是否需要协调？ | 固定机制四组对照及条件分工扫描 | 有可解释的相互影响且静态组合不足 |
| S / V | 什么方法值得实现，最终收益如何？ | 条件式原型、独立确认集 | 正确性、净收益、强基线、消融均满足 |

依赖关系：U0 开始，U1/U2 与 P0 的必要正确性工作交错推进；数据路径、预算与观测校准通过后再完成 M1。M2—M4 属于 A，M5—M6 属于 B，两条分析线可分别推进，但性能测量串行运行。M7 等两条线都有可复现现象后再做。现有完整路由的离线分析可提前进行。

前期只执行固定规则和明确干预；依据现象形成 S 阶段算法。离线诊断先行，不要求一开始实现完整控制器。

- 新实验产物根目录为宿主机 `/home/cuichengshang/moe_ssd/test/motivation/`，容器内 `/ssd/test/motivation/`；这是规划路径，本文不创建实验目录或启动实验。源码设计文档保存在 workspace 的 `docs/`。
- 沿用 Qwen3-30B-A3B BF16，48 层、每层 128 个路由专家，decode 每 token 选 8 个。逻辑专家三投影各约 3 MiB，合计 9 MiB；执行前依据 GGUF 实际形状和格式再次确认。
- 开发集沿用 `/ssd/test/m0/datasets/public-mirror-v4/dev.json` 的 12 请求，四域各 3 条；确认集为同目录 `confirm.json` 的 48 条来源分离请求。
- 首轮小试从开发集每域预先按固定 ID 次序选 1 条，最多 32 个自然生成 token；用于估算耗时与筛查粗配置。正式开发实验用原 12 条、最多 128 token、遇 EOG 停止。短版独立建 manifest，不能混入原 M0 结果。
- 原 12 请求冻结续写实际共 1145 token，不能当作 12×128 个样本。主要单位为独立请求，分开报告 prefill/decode。
- B 的 decode 微基准使用真实权重及捕获的真实层输入、路由和混合权重；prefill 扩展使用每专家 token 行数和实际激活专家数，不能假定整个 prefill 批次只激活 8 个专家。
- 首轮沿用约 256 token 的 prompt，少量 2048 token 上下文作为后续扩展；重新冻结时单独记录模板、截断、实际 token 长度和哈希。
- BF16 是正确性与机制开发点。论文相关工作采用多种量化格式，正式方案冻结后如已有兼容权重及 CPU/GPU kernel，再以同一个低比特格式增加独立验证点；该点各对照使用相同权重，单独报告字节、准备成本和路由，不将 BF16/低比特速度差当调度收益。没有该验证时不推广到低比特模型。

### 3.2 统一内存与读盘口径

设总物理预算为 `B_total`。至少核算非专家权重、KV、专家唯一有效权重、真实副本、在途读取缓冲、执行目标、工作区、页缓存与运行时开销；物理别名不重复计数，不把 RSS 与 cgroup 计数相加。

先实测公共固定开销 `B_fixed`，再在可实现的专家相关总池 `B_expert = B_total - B_fixed` 上选择 4/8 GiB，16 GiB 作扩展。`B_expert` 包含驻留、读取中、就绪未用及计算使用中的全部专家相关缓冲，不能把 8 GiB 缓存参数称作总物理预算。依赖配置变化的工作区不能全部藏入公共固定开销。

首轮预算点不足以容纳实际工作区和需求保底槽时，标为不可行并调整到预先记录的下一个预算点。不得通过 OOM、swap 或忽略临时副本实现所谓小预算。

模型当前能在 DGX01 的物理内存中全驻留，论文应明确这是受控预算实验。全驻留是放宽容量约束的参考，不是相同小预算下的可部署基线。

主 I/O 对照使用相同显式 direct-read 路径并记录实际成功/回退。mmap 单独标注为页缓存受影响的基线。direct 请求长度、进程实际读字节、块设备读字节分别报告；它们不等于 NAND 物理读量。禁止清理整机页缓存或修改共享容器的全局内存限制来制造结果。若需要隔离限额，后续实施时另行设置和验证仅覆盖实验进程的资源域及驱动分配可见性。

如果总预算无法可靠约束，首轮明确只做固定缓冲/应用分配预算的机制微基准，暂不宣称相同总物理预算下的系统收益。

v2 明确划分三种容量区域，先用路由计算预注册时间窗口内唯一专家权重工作集，并同时报告全专家池大小：F，全驻留放宽参考；W，同一约束预算可容纳所研究工作集；O，同一约束预算不能容纳且确认持续发生后备读取。工作集窗口必须固定，例如 1/8/32 个 decode token，不能根据哪个窗口有利而事后选择。4/8/16 GiB 只是 U1 后可行时使用的起点，不能通过忽略固定开销得到这些标签。

每个对照必须同时报告总专家相关池、唯一可执行权重、真实副本、峰值在途和页缓存。只固定唯一权重数的 U1 对照用于隔离路径成本，不用于声称同总预算获益；总预算对照才允许容量差异自然影响命中率和读取量。

主结论使用预分配、可记账的需求/预取池并验证持续 SSD 读取。buffered/mmap 是系统敏感性对照，分别报告 OS 自然页缓存状态，不能给其他方法全模型页缓存却称同预算。采样的 RSS、驱动和 cgroup 统计需说明覆盖范围；`nvidia-smi` 的本机显存字段可能为 Not Supported，不能把缺值记为 0。当前 M0 未证明总物理预算已经被执行。

### 3.3 预测、布局、缓存与执行公平性

- 第一版预测固定为上一 decode token 同层 Top-K；首个 token 使用无预测，或统一使用已完成 prefill 的末 token 路由，二者在开跑前择一冻结。所有候选只能在对应历史真正完成后产生。
- 原始未来路由只用于标记为 oracle 的诊断参照，不能用于在线配置选择。预测查表/生成时间计入在线时间；观察预测不刷新真实访问热度。
- 每个候选包含目标 token/层、产生时刻、专家 ID、来源和固定规则下的置信信息。跨策略固定候选及其逻辑产生事件；闭环执行中墙钟产生时刻允许随真实进度变化。
- 第一版真实 router 与完整专家执行不变；错误预测只能浪费资源，不能替换选中专家。
- 原 GGUF 中三个投影未必连续。涉及 9 MiB 整专家读取时，先制作经过逐字节校验的 sidecar；同一对照全部使用同一布局。布局收益单独测量，不能与调度收益混合。
- A 阶段固定缓存替换规则，先用 LRU 做机制隔离，最后需加入老化频率/未来使用等相关强基线；不能仅胜过 LRU 就声称超越已有工作。
- B 阶段固定起始缓存、读取对象与读取顺序，先固定并发，再在 M6 单独改变它。CPU/GPU 格式转换、预打包、输入分发、输出归并和额外副本都计时计空间。
- CPU 使用本机可用且经过核查的优化实现；记录 Arm 核拓扑、可用指令、线程池和绑定。不能用明显低效的标量 CPU 实现代表 CPU 上限。
- U1 冻结的数据路径 P*、权重布局及执行表示在主线各策略间保持一致。若更换路径，单独重做路径对照，不能同时启用零复制/持久槽和调度算法后把全部收益归给后者。
- 读取并发与 CPU 线程数是不同变量。当前阻塞 `pread` worker 数可能限制可提交并发；改变 worker 也会改变 CPU 调度成本。实验记录应用已提交/未完成请求数，不能把 worker 数直接称为 NVMe 硬件队列深度；需要独立控制时使用固定 worker 预算及提交限额，能力不足则声明耦合。

### 3.4 测量与统计

正常性能路径新增低扰动事件；避免每节点同步和每次读取打印。使用异步缓冲与阶段末收集，独立测量观测开销。CUDA 设备事件只在可关联的设备时间线内比较，不能与 host 单调时钟直接相减。

新增或补齐：`candidate_created`、`slot_reserved`、`demand_revealed`、`read_queued/submitted/completed`、`executable_ready`、`compute_submitted/completed`、`merge_completed`、`slot_released`、`evicted`。每条关联 request/token/layer/expert、候选目标、字节数、设备、allocation ID、需求/预测属性及触发原因。

进程中的申请槽位、CPU 实际可读、GPU 实际可消费是不同状态；不能把 `pread` 返回等同于 GPU 可消费。多投影数据须正确关联。

共享槽上 CPU-ready 与 GPU-ready 的时刻可能在完成必要同步后重合；复制型路径中二者可能不同。分别记录 `read_done`、`cpu_ready`、`gpu_ready` 及其实际因果边，不人为插入固定 H2D 阶段。原权重主要只读，控制元数据和输出归并的同步仍需显式正确，硬件一致性不等于可以省去生命周期或数据竞争处理。

主要指标：TTFT、每请求 TPOT、请求内 token 延迟 p95、层完成时间。解释性指标：读取服务时间、软件排队时间、按期补齐缺失专家比例、错预取字节、补读、就绪未用 byte-ms、CPU/GPU 分支完成及合并成本。

实际等待通过 host 阻塞区间、设备依赖和消费者事件关联识别；并行 worker 的读取耗时不能求和当 GPU 等待。设备空闲区间也可能来自调度、计算依赖或其他工作，需按原因归属。无法精确分解时，主张止于端到端处理差值，不能伪造可加的等待分项。

微基准按随机交错的配置顺序至少 5 个独立测量块，先短试测方差；正式前向先做 3 轮配对交错测时。以请求或来源组为重采样单位报告配对置信区间，不把同请求 token 当独立请求。12 请求的尾延迟只作探索，48 请求确认集再检查稳定性。

所有最优固定配置在开发集选定、确认集冻结；逐事件遍历未来的最佳配置只作诊断参照。建议进入完整原型的工程门槛为：代表性负载上主指标改善至少 5%，且超过观测和控制开销；该数值是预注册的资源投入门槛，不是学术贡献标准。开跑前可与导师调整，看到确认结果后不得调整。

## 4. UMA 前置校准与 P0

### 4.1 U0：冻结本机能力，建立访问路径账本

核对：Docker 服务与挂载；GPU/CPU 型号、CPU 核组/可用核掩码；系统页大小、NUMA 可见性、驱动/CUDA 版本；SSD 型号、文件系统、挂载、direct I/O 对齐要求及已存在的系统负载。记录能观测到的 GPU/CPU/SSD 温度、频率和功耗状态，不更改共享机器全局设置。

对 system-allocated、mapped host、managed、CUDA device 分配分别查询当前 runtime 支持的可访问/并发属性，并做小范围实际访问与可见性校验。确认原 ggml kernel 的指针、布局与 buffer-type 约束；CUDA kernel 能读某指针不代表整个后端无需适配就支持它。

对 CPU 可写且合法的 I/O 目标做 direct-read 对齐与完成校验；不把设备指针直接传给 `pread`，不假定 managed/mapped 分配必然满足文件系统 direct I/O 要求。任何失败/回退进入 manifest。一个能力测试不支持时保留明确的复制路径，不能绕过验证。

每份专家数据建立 allocation ID、分配 API、大小、别名关系、CPU/GPU 访问方式、创建/释放和最后消费者记录。还要覆盖对齐 bounce 区、CUDA 执行目标、工作区、转换副本与页缓存。分离虚拟映射大小、实际驻留和分配承诺。

交付 `platform.json`、`access-paths.json` 和分配账本，全部归档至指定 test 根目录。U0 是环境事实验证，不是性能创新。

### 4.2 U1：数据路径和真实可执行容量

在同一权重与读取布局下，按可实现性逐步测试以下路径；这些是待实现对照，不是现有功能声明。

| 路径 | 数据组织 | 要检验的成本 |
| --- | --- | --- |
| Pcopy | 当前 direct bounce、缓存 entry、CUDA 目标及重复提交 | 留存现有基线，测内存内复制和源/目标重叠生命周期 |
| Pslot | 持久 GPU 可执行槽，命中复用；保留必要 staging | 不改变权重计算内容时，避免重复准备的收益与槽映射成本 |
| Pshare | 能力允许时，SSD 写入合法共享槽，CPU/GPU 消费同一份只读权重 | 避免显式副本是否被访问效率、页表、同步或 kernel 限制抵消 |

若 Pshare 仍需要 staging，则明确写出实际路径与副本，不能标为真正单份权重。Pslot/Pshare 涉及紧凑槽索引或 kernel 适配时单独记录，先用单层原型验证。

先做相同唯一专家容量对照，测命中时准备字节、kernel 时延和同步；再做相同总物理预算对照，允许唯一专家容量不同，测净读取量及层时间。至少包含一次性冷用和反复热用；报告首触/初始化与稳态成本，不能仅依赖热页结果选路径。

依据开发数据冻结适合本机的 P*，并保留 Pcopy 作为历史路径对照。Pshare 不必胜出；若只部分负载适用，先固定各明确条件下的路径，避免未解释的动态路径切换。

### 4.3 U2：共享资源与功耗条件下的服务曲线

使用真实专家形状和固定请求集合，依次测：SSD 读取；CPU 专家；GPU 专家；路径所需复制；以及 I/O+GPU、CPU+GPU、I/O+CPU、三者共同运行。U1 去除不必要复制后重测关键组合，区分软件额外流量和不可避免的专家工作。

先在驻留数据上测计算并发，再恢复真实 SSD 供给。每阶段先固定总 CPU 核额度和读取并发；核组对照使用同样数量的实际可用核。I/O 服务线程预留相同额度，计算线程不得挤占后再把退化归因于 DRAM。

交付条件服务时间、层完成时间、读取响应和可观测频率/温度。共享带宽竞争、SoC 功耗/频率变化、线程争用、页表/首次访问、软件复制分别列为可能原因。没有计数器或受控干预支持时只称并发干扰；不能把官方 273 GB/s 与逻辑读写字节之比当作实测带宽饱和证据。

后台服务活跃且无法排除干扰时，对测量块标注污染并重测；不停止其他用户服务。不强行锁频；记录状态并使用交错顺序，对明显不同热状态单独分析。

### 4.4 P0：正确性和测量资格

交付：M0 四基线真实 BF16 正常路径正确性及测时；U1 的 P* 正确性与实际可执行容量；观测开销结果；F/W/O 区域和可执行预算点。既有 M0 验收与新 P* 验收分开归档。

原正式实验保留。重试新实验名称，依据短试调整每基线超时，例如 10800 秒起步，并按请求写进度；不能覆盖超时产物或仅延长时间后默认通过。原审计中的 `m0_accepted=false` 占位不能当全部研究协议的自动判定。

CPU 和就绪分组执行属于新路径，分别验证完整 Top-K、权重身份、无漏算/重算以及输出归并。沿用现有 BF16 logits `atol=1e-3, rtol=1e-4` 和 top-1 检查作为初始门槛；若新算子归约不满足，先定位误差，在独立校准数据上另立数值协议，不能在确认集上放宽阈值求通过。自然生成及任务质量另行验证。

P0 不妨碍先用现有完整路由做离线分析；新端到端性能结论必须等对应路径通过。不能只把 `--cache-mib` 改小就宣称 P0 的 UMA 预算验收完成。

## 5. M1：确认 SSD 关键路径和可优化上限

问题：在 U1 冻结的本机 P* 上，慢主要来自 SSD 服务量、缺少提前量、等待整组权重，还是不可避免的准备/执行开销？Pcopy 的额外复制成本在 U1 单独解释。

处理：F 全驻留参考；P* 上 W/O 两类容量区域的 GPU 需求卸载；在相同专家对象和准备路径下使用内存后备源的机制对照。内存后备源属于放宽容量/存储约束的诊断参照，不能当同预算可实现方案或严格唯一的 I/O 因果归因。O 组必须观察到持续的实际 SSD 读取，而非只在模型初始化时读盘。

实测固定缓冲下本机 3 MiB 读取的吞吐与延迟，并采集真实路由下每 token 需求字节、可执行就绪到达和消费者时间。若使用 sidecar，增加 9 MiB 请求但不混入布局变化。

主图：各请求正常 TPOT 与放宽参考；每 token 实际需求读量；权重到达与消费者执行时间线。`读取字节/实测带宽` 只作供给量级估算，不能忽略并发、突发性与缓存后称为严格 token 延迟下界。

补充三个跨配置比较坐标：`相同条件下专家读取时间/GPU 专家执行时间`、`预注册窗口内唯一权重容量/该窗口工作集`、`额外复制字节/实际供给有效权重字节`。这些是解释不同精度、形状和路径的诊断量，不是性能保证或独立可相加成本。论文中的设备结论只在相近的实测区域讨论迁移。

决策：若主要时间是必须读取的字节且几乎没有可重叠工作，A 优先研究减少补读/缓存保留，B 的潜在收益上限很小；若权重逐步就绪且仍等待整组，进入 M5；若更早供给明显有空间，进入 M2。

## 6. M2：预取需要多少提前量，现有信息能否提供

问题：当前缺的是预测准确度、可用提前量，还是读取服务能力？

采用四组：按需；固定历史预测；相同候选产生事件提供正确未来专家的 oracle；放宽读取等待的参考。统一采用 P*，oracle 仍受本机读取服务与给定缓冲约束；参考不是可部署结果。可执行就绪时间从 U0/U1 的真实路径得到：共享槽可能只有完成通知与必要同步，复制型槽则保留实测的复制/准备阶段。

在离线正常时序驱动的回放中先扫目标前 1/4/16/48 层开始读取，仅在候选已经合法产生的区间内启动。历史预测不够早产生时记录信息不可用，不能补造过去的预测。同时报告正常 P* 路径下的毫秒提前量，以及 `可用提前量/同状态准备服务时间`，不能直接沿用独显论文的若干层窗口或假设各层等时长。

先保持同一起始驻留和明确足够的固定缓冲，隔离供给提前量；再让 M4 引入受限空间。开环回放的到达时刻对所有处理相同，用于机制比较；实际前向闭环重新产生时刻，以捕获调度改变执行速度的反馈。

指标：缺失集合预测召回、目标前可执行就绪率、迟到量、读取放大和 TPOT；热门已驻留专家的预测命中不能算节省了一次缺失。

判定：oracle 也迟到，先优化准备窗口/供给，训练更准预测器无法单独解决；oracle 明显好而历史预测几乎无用，则现有信息不足，先适配一个已有预测器再讨论调度；历史预测已经提供有效候选，进入 M3/M4。未来信息参照只说明空间，不证明已有轻量预测能够实现。

## 7. M3：需求优先级能否穿透在途 SSD 读取

问题：软件优先队列能否抵消此前提交的预测读对新真实需求的影响？

固定起始数据、候选、到达时刻、布局和缓冲池，关闭缓存替换，使用真实 direct I/O 回放。先测 I/O 单独运行，再只对少量入选配置增加相同的真实 GPU 消费流，检查共享内存访问是否改变最佳提交额度。第二步固定 GPU 工作和输入；不能把吞吐变化都归给 SSD 队列。

| 处理 | 规则 |
| --- | --- |
| Q0 | 仅真实需求，观察没有投机流量的参考 |
| Q1 | 整专家预测读，软件队列需求优先 |
| Q2 | 固定分块预测读，需求优先，需求到来后暂停新增投机提交 |
| Q3 | Q2 加提交前的未完成投机字节上限 |

Q1/Q2/Q3 最终完成同一批对象，并 drain 全部任务，记录实际对齐字节；需求与在途预测重合时 join，禁止重复读取。Q0 工作量不同，不能靠 Q0 与 Q1 差值独自证明队列问题。

起始配置：块 1/3/9 MiB，应用未完成读取额度 1/4/8；U0/U2 确认本机对齐与服务曲线后执行。先在 3 MiB 下扫额度，再在代表性额度扫粒度，最后只补少量交互组合。未完成投机字节上限取 1/2/4 个逻辑专家的量级，实际按对齐字节执行。只在确有 submit/completion 证据时报告应用在途量；不把线程数当设备队列深度，也不假定取消系统调用能立即抢占设备操作。

记录需求入队到提交、提交到完成、总响应时间、需求到来时的预测在途字节以及总吞吐。主图为“吞吐—需求 p95”折中和“预测在途字节—需求响应”。块设备共享计数只作旁证。

判定：固定 Q2 已稳定解决则作为公共基线；Q3 能在相同工作量下恢复需求响应且最佳额度随需求变化，才有存储感知准入的算法动机。选择两组进入真实前向检查 TPOT，不能把离线队列改善直接称为推理加速。

## 8. M4：分阶段占位是否减少额外缺失

问题：预测生成与空间预约绑定，是否让远期对象过早挤出近期有用权重？

“分阶段”在首版中定义为：候选登记（仅元数据）、预约共享物理池中的容量并提交读取、完成 P* 所需的就绪处理、真实使用后决定保留。阶段按依赖定义，允许没有显式复制；不套用 SSD–RAM–VRAM 三个物理层。读取开始前必须有合法目标缓冲；暂不涉及压缩物化。

固定 M3 选出的一个 I/O 配置、同一候选及产生事件、缓存替换规则、P* 和总专家相关池。读取目标与执行源为同一分配时按 allocation ID 只计一次；存在 staging/执行副本时按实际重叠时段计入。若 P* 仍需多个逻辑池，它们共同受一个物理预算约束。

| 处理 | 规则 |
| --- | --- |
| R0 | 无预测，需求读取与普通缓存 |
| R1 | 候选产生即预约/读取，预测就绪对象保护到目标处理 |
| R2 | 先登记候选，到固定目标前距离再预约/读取 |
| R3 | R2 相同起读规则，允许重新评价未被真实消费者使用的预测就绪对象 |

R2 对 R1 隔离占位时机，R3 对 R2 隔离保护期限。读取中、复制中、计算中以及已有真实消费者引用的对象始终不能回收；R3 只允许安全取消尚未兑现的预测保留。

开发扫描距离 2/8/24 层，在 U1 确认可行的专家相关总池上选择两个压力点；4/8 GiB 仅为初始候选，同时包含 W/O 边界。另保留一个空间充足的负对照，确认占位冲突只在相应压力区域出现。不足提前距离时从最早合法事件开始。对可能改变未来内容的淘汰，配对记录各处理独有的缺失和净补读，不把每次驱逐都当损失。

输出：预约未就绪、就绪未使用、使用中和使用后保留的 byte-ms；被预测驱逐对象的真实再访问；补读字节；迟到；TPOT。主图将提前距离与空间占用、净补读、迟到放在同一请求配对数据中。

成立条件：提前占位增加额外缺失，延后可减少该损失，但继续延后又产生迟到；变化在真实前向仍成立。若仅为预测错误带来的多读，优先缩减预测范围；若单个固定距离足够，则先采用固定方案。最优时机随空闲空间和服务时间改变时，再设计分阶段控制。

## 9. M5：CPU 是否能利用 SSD 等待期间的就绪工作

问题：在本机 P* 上，权重陆续到达时，CPU 是否能够比强 GPU 路径更早完成这层？CPU 的候选收益来自额外执行能力、减少实际准备/排队或尾部工作；不预设存在可省去的独显 PCIe 传输。SSD 中缺失的权重仍须读取。

先实现一个真实单层执行原型：匹配的 gate/up/down 与层输入对目标设备可用后才可执行专家，按原 routing weight 汇合所有输出。CPU 分支若需要额外权重格式/副本，把准备过程加入依赖图及空间账本。首版以完整专家为执行任务，是否需要拆分原 fused 图是明确的实现成本。

必须有以下对照：

| 处理 | 执行方式 | 用途 |
| --- | --- | --- |
| G0 | 在 P* 上等所有选中权重准备好，GPU 统一执行 | 同路径整组屏障参照 |
| G1 | P* 上已就绪专家在 GPU 执行，调优小分组以摊薄启动开销 | 排除单纯去掉屏障的收益 |
| H1 | 与 G1 相同 P* 和就绪机制，CPU 分担固定数量 | 测 CPU 独有的净贡献 |
| C0 | CPU-only | 执行能力诊断，不作为主要弱对手 |

H1 必须优于开发集选定的最佳 GPU-only 策略（包括 G0/G1 及其分组参数）。若只优于 G0、不优于 G1，则收益主要来自就绪驱动；若 G0 的融合效率使其更快，也不能忽略 G0。CPU 分支导致图拆分、融合变化或 launch 数变化时，增加匹配分组的 GPU 对照并报告差异。

两步执行：先用已驻留真实权重按冻结就绪序列释放执行许可，隔离执行调度；该序列优先来自 M1 正常样本。随后在相同起始缓存和真实 SSD 读取下重测，检查加入 CPU 是否反过来改变权重到达。人为释放只用于控制机制，不算真实 SSD 加速结果。

初始配置：decode Top-8，起始就绪专家数 0/2/4/8，CPU 分担 0/1/2，计算线程 1/2/4；线程数不超过 U0 确认可用核额度。先固定 I/O 并发和一种核组，在入选配置上比较相同核数的另一核组及分离 I/O 核组。从少数代表性组合筛选，未就绪专家必须等待。全未就绪、全部已就绪和部分就绪均保留为边界对照；若收益仅发生在全部已就绪场景，应归为计算分工效果，不能宣称隐藏了 SSD 等待。

测量：层输入和当前状态可用至输出归并完成的总时间、真实读取完成时间、CPU/GPU 分支、输入/权重准备、kernel 启动和归并成本，以及用于 I/O 的 CPU 时间。所有额外格式转换和准备均记录；一次性预处理同时报告冷启动和稳态摊销。

主图：就绪专家数/本机实测供给间隔与 H1 相对最佳 GPU-only 的收益；CPU/GPU/读取时间线。把 U2 并发服务变化与实际层完成时间同时画出。仅当 H1 在自然负载可出现的状态下优于最佳 GPU-only，才进入完整 CPU 协作原型。若作用只是避开 Pcopy 的冗余准备而在 P* 上消失，优先采用更好的 GPU 数据路径。

## 10. M6：并发干扰是否要求动态分工

问题：计算和供给并发时，独立测量得到的最佳配置是否选错，最优配置是否随状态改变？复用 U2 的服务曲线；U2 负责基础访问/干扰校准，M6 负责真实路由与输入下的决策错误，避免重复全量扫描。

固定相同真实权重、输入、SSD 读取集合和总 CPU 核配额，对 GPU、CPU 专家计算、I/O 加必要准备做独立、两两与共同执行。第一步读取请求序列独立于算子，隔离资源竞争；第二步恢复实际数据依赖，观察层完成时间。

保留固定 I/O 服务核或线程配额，CPU 专家线程只能使用剩余预算；总核数相同。根据实际拓扑确认核组后才绑定，不按 CPU 编号猜快慢核。应用读取额度先取 1/4/8，沿用 M5 筛选的 CPU 配置与 P*；prefill 每专家行数 4/16/64 为后续验证，不一次展开全部组合。

对比三类决策：开发集最佳固定配置；根据独立测得时间及合法数据依赖选择的配置；使用当前缺失字节、就绪专家数、读取状态和 token 行数的条件成本配置。最后一类在动机阶段先做训练/验证分离的离线模型，暂不实现完整在线控制。

指标：层完成时间预测误差、配置排序反转率、误选时间损失，以及条件模型在留出请求上的纠正量。逐事件实测最佳只作诊断 oracle，不用于线上。

不能仅凭 CPU/GPU 同时变慢就断言共享 DRAM 饱和；还需排除 CPU 线程争用、SoC 功耗/频率变化、复制和启动开销。记录可观测的 CPU/GPU 频率及温度，分离短时冷态与持续负载；不能将 shared-memory 带宽与共享功耗预算的影响混成同一原因。缺计数器时结论写为观测到的并发干扰。

成立条件：最优配置确实变化，独立模型反复误选，条件模型可在留出状态改善且开销小于收益。若最佳固定配置已足够，交付静态分工及适用范围，不增加动态控制。

## 11. M7：两条主线的相互影响

先用开发集选定的固定干预，不依赖尚未实现的新算法。A* 为 M3/M4 验证有效的固定提交额度与分阶段开始规则；B* 为 M5/M6 验证有效的固定分工。记 G* 为开发集选出的最佳 GPU-only（G0/G1 及分组参数）。四组共享同一 P*、数值格式、布局、核配额、总物理预算、容量区域和合法预测信息；不在启用 A/B 时同时切换共享槽、量化或缓存表示。

| 处理 | 供给策略 | 执行策略 |
| --- | --- | --- |
| J00 | 调优普通需求/预取基线 | G* |
| J10 | A* | G* |
| J01 | 普通基线 | B* |
| J11 | A* | B* |

如果 T 表示配对请求的原始延迟，比较 `I = T11 - T10 - T01 + T00`，并给出区间。I 仅衡量该配置下的交互，不等于联合算法收益，也不用加速比相加判断。

同时记录：A* 是否改变就绪专家数量和可重叠时间；B* 是否改变读取服务及预取按期率；不同 A 配置下最优 B 配置是否变化。空间占用和实际读量可能随策略改变，应全部保留而非人为修正成相同字节。

四格实验只能说明是否存在交互。若要提出联合控制，还需证明调优后的独立策略组合仍有稳定损失，并在留出请求上由状态相关选择恢复。若 A 使 CPU 可利用窗口消失，则最终方案可以在该状态自动关闭 CPU；若二者基本独立，则采用模块化组合。

## 12. 实验结果如何导出方案

### 12.1 A：存储感知的分阶段预取与驻留

M2—M4 成立后才实现。状态至少包括候选生成、本机条件读取服务时间、P* 必需的就绪处理、当前共享池空闲槽、受保护在途量、未完成需求及受害对象可能的补读代价。维护 CPU-ready/GPU-ready 的真实状态，不以 CPU cache/GPU cache 名称推断两份物理容量。

初版在少量开发集实测配置中选择：是否准入、预计能按期完成的开始区间、提交额度、就绪预测保留期限。开始区间是带测量不确定性的估计，不是 SSD 延迟的确定性保证。需要同时有合法目标空间与允许的 I/O 额度才能启动；按 U1 验证的最低可推进配置预留真实需求缓冲，空间不足时拒绝预测而非阻塞全部需求。截止期来源是过去正常执行的进度估计，不使用未来真实运行时间。

提出一个易验证的规则起点：当预期剩余准备时间接近估计消费时刻时才预约；若提前预约预计产生的补读损失更高，则延后或拒绝；一旦目标路由揭示，真实需求优先，错误且未执行的预测释放安全保留。只有超过最佳固定距离、分块与在途额度组合时，才主张自适应控制价值。

分开报告：减少迟到的收益、减少补读的收益、去掉重复复制的工程收益及控制器开销。

### 12.2 B：按就绪状态和并发成本选择 CPU/GPU 分工

M5—M6 成立后才实现。初版从少量 `CPU 专家集合、CPU 线程数及核组、应用 I/O 额度` 配置中选择；先冻结一种核组配置再增加必要候选。集合候选必须考虑目标设备实际可访问、权重就绪和表示准备成本，不能只按专家个数假定等价。仍未读入的专家不能因改为 CPU 执行而跳过 SSD 供给。

预测目标是当前剩余任务依赖图的归并完成时间，包含设备排队、权重准备、执行、同步与归并；不能直接用各专家孤立执行时间加到 ready 时刻再取 max，忽略共享设备上的串行与并发干扰。

使用条件查找表或低维回归，在线低频修正。预测净收益小于估计不确定性与调度开销时采用 G*；CPU 无收益状态保留为合法结果。条件模型仅使用上线可观测输入，不依赖测不到的实时物理 DRAM 占用率。U0/U1 验证过的源指针可访问性、布局与算子兼容作为硬约束，不能默认零复制。

### 12.3 联合范围由 M7 决定

| 观察 | 方案范围 |
| --- | --- |
| A 明显有效，CPU 无净收益 | A 为主，CPU 负责 I/O 与控制 |
| CPU 有收益，最佳分工稳定 | A 加固定 CPU/GPU 分工 |
| A 有效，分工随供给状态变化 | A 输出实际准备状态，B 据此选择少量配置 |
| 双向影响显著且独立组合不足 | 共享状态与预算，联合选择准备额度及执行配置 |
| 两条主线均缺乏显著空间 | 保留强基线，转向辅助方向的可行性筛查 |

主线 A 的候选贡献为共享物理池约束下准备时机、实际存储在途量与驻留代价的联合决策；主线 B 的候选贡献为同一数据路径上权重就绪条件及共享资源成本下的专家执行分工。U1 的副本消除或更换分配方式作为公共底座单独消融；只有实验支持且相对相关已有机制有增量的部分写为最终贡献。

## 13. 辅助研究点的触发条件

- 布局：U0/U1/M1 显示对齐 bounce、碎片读取或实际准备明显影响服务时间时，比较原 GGUF 与校验过的 sidecar；随后所有调度对照采用同一布局。U0—U2 的核实本身不要求先制作整模型 sidecar。
- 计算分块：M2 的提前窗口确实不够，M5 显示整专家就绪粒度限制并行时，才验证配对中间维切片；与 M3 的 I/O 分块区分。
- 压缩：M1 显示必须读取的字节占主导时，先测真实压缩率、解码及干扰，收益成立再增加表示状态。
- 缓存组合价值：M4 的补读代价不能被简单规则解释时，再研究 Top-K 组合缓存。
- 预测器：M2 的 oracle 与合法历史预测差距显著时，先适配已有预测器；训练数据、开销和确认集隔离单独记录。

每次只加入一种辅助变化并保留消融，避免把新增模块数当作创新数。

## 14. 最终验证、产物与实施顺序

所有新增微基准、代码执行与性能测量均在现有 Docker 内完成。每次执行使用新的 `/ssd/test/motivation/<experiment-id>/`，保存 `manifest.json`、配置、命令、源码/二进制/模型/输入哈希、实际顺序、逐请求指标、轻量事件、内存与 I/O 观测、退出状态及报告。完整高开销诊断只覆盖必要正确性样本。

复用现有构建与数据，不把尚未实现的实验标为现有 CLI 命令。需要新增的工具按依赖顺序为：U0 能力检查与低扰动物理账本、U1 单层路径原型、U2 服务校准、路由/容量回放、固定缓冲 I/O 回放、单层就绪分组 GPU/CPU 原型、条件成本拟合、在线策略。先列每个工具输入/输出 schema 再实现。

首批顺序修改为：核实原 Docker 环境可见性；U0；U1/U2 与 P0；固定 P* 与可行容量区域；M1；M2 粗扫描和 M5 单层筛查。接着按通过的分支做 M3/M4 或 M6，最后 M7。U2 只做少量代表组合，M6 复用其曲线。每轮只把最有解释力的 2—3 个处理送入完整前向。

最终确认至少包含：四域 48 条冻结请求、3 轮交错测时、两个可行预算点及 W/O 区域、F 参考、短/较长上下文、CPU 关闭状态、正确性与自然生成检查。持续高负载与短时测量分别记录功耗/热状态；有兼容实现和资源时加入同格式对照的低比特点或第二模型。冻结所有参数后才打开确认集，不根据其结果逐请求选择配置。

完整推理性能比较包括实际准备、预测、CPU/GPU 执行与归并开销；冷启动/模型加载单独报告。算法稳定收益需同时超过调优静态方案与相关论文机制适配，并通过只启用 A、只启用 B、独立组合、联合控制的必要消融。若只支持一个 BF16 模型，则论文结论明确限定该范围。

每项实验交付一页：假设、唯一干预与公共变量、原始证据、主要指标及不确定性、是否恢复所怀疑问题、继续/停止决定，以及需要实现的最小方案。完成该页后再扩大实验。
